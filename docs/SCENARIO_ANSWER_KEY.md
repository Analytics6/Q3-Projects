# Finwell Backend Scenarios: Instructor Answer Key

Use this file for facilitation and review. Source references identify the primary investigation point; a complete solution may touch more than one module. The student workbook intentionally asks learners to find these locations.

## A. Flask API, authentication, and authorization

| # | Primary source location | Expected investigation / review notes |
|---|---|---|
| 1 | **backend/app.py — register()**; **backend/database.py — users schema** | Email is trimmed/lowercased before insert; the email column is UNIQUE COLLATE NOCASE. The handler catches an integrity error by checking for “unique” and returns 409. Verify rollback occurs before another query and test capitalization variants. |
| 2 | **backend/app.py — payload(), http_error(), unexpected_error()** | request.get_json(silent=False) can raise an HTTP exception. The HTTPException handler returns a JSON envelope. Check malformed JSON, wrong media type, JSON null/list, and invalid object separately; add explicit 400/415 handling if API contract needs stable codes. |
| 3 | **backend/app.py — register()**; **backend/database.py — users schema** | Account creation enforces 12–128 characters and stores generate_password_hash(..., method="scrypt"). A reset endpoint needs a high-entropy single-use expiring token, generic response, rate limit, token hashing, and audit event; never accept an unauthenticated direct password overwrite. |
| 4 | **backend/app.py — get_conversation(), get_conversation_endpoint(), delete_conversation(), get_messages(), send_message()** | Ownership filter is WHERE id=? AND user_id=?. Messages are retrieved by conversation ID only after ownership is checked. Any new direct message route must preserve that check. |
| 5 | **backend/app.py — admin_required(), user_from_token()** | The decorator reloads role from the users table on every protected route. A demoted user should get 403; nonexistent account should get 401. Verify no privileged role is trusted from client input. |
| 6 | **backend/config.py — JWT cookie settings**; **backend/app.py — enforce_request_origin()** | Production requires Secure cookies; JWT uses HttpOnly access cookies, SameSite=Lax and CSRF. Check actual origin, scheme, frontend origin, proxy/TLS setup, cookie path, CSRF cookie/header behavior, and deployment hostname. Do not weaken Secure/CSRF globally to mask a deployment mismatch. |
| 7 | **backend/config.py — JWT_CSRF_* settings**; **backend/app.py — enforce_request_origin()** | CSRF protection applies to POST/PUT/PATCH/DELETE via Flask-JWT-Extended. Origin check is an additional control. Test missing/invalid CSRF token, absent/disallowed Origin, and legitimate same-site request. |
| 8 | **backend/app.py — login(), unexpected_error(), request hooks** | Current handlers do not log passwords intentionally. Never log request bodies for auth routes. Use request_id, route, status, latency, and a safe account identifier or keyed hash; redact credentials and tokens from exception context. |
| 9 | **backend/app.py — Limiter initialization and route limit decorators**; **backend/config.py — RATELIMIT_STORAGE_URI** | Local default is memory://. Production requires REDIS_URL in create_app(). Validate a shared Redis backend and failure policy across instances; avoid silently falling back to per-process limits in production. |
| 10 | **backend/app.py — has_unsafe_secret(), send_message(), one_turn_chat()** | A regex-like heuristic rejects suspected card numbers/CVV/PIN/OTP before model call. It is incomplete and can both miss and falsely flag data. Add request minimization, redaction, provider logging controls, security monitoring, tests, and explicit policy; do not claim PCI compliance from this check. |
| 11 | **backend/app.py — http_error(), rate_limited(), unexpected_error(), send_message(), one_turn_chat()** | Public errors are generic JSON; unexpected exceptions are logged with request_id. Ensure error objects, secrets, prompts, and customer content are not returned. Correlate with X-Request-ID and structured logs. |
| 12 | **backend/config.py — MAX_CONTENT_LENGTH**; **backend/app.py — upload_knowledge()** | Global request cap is 4 MiB while per-file validation permits up to 10 MiB, and multiple files are allowed. Align total request limit with aggregate file policy and multipart overhead; return a predictable 413 response. |
| 13 | **backend/app.py — upload_knowledge()**; **backend/rag.py — index_pdf_bytes(), _save_document()**; **backend/database.py — documents schema** | Default source ID is derived from filename and relational uniqueness is filename-based. Same filename therefore behaves as replacement. Define immutable/versioned document IDs or content-addressed IDs; atomically coordinate vector removal, insertion, and relational status. |
| 14 | **backend/app.py — upload_knowledge(), begin_run(), finish_run()**; **backend/rag.py — index_pdf_bytes()** | Vector writes are external side effects and cannot be rolled back by SQLite rollback. A production design should stage, record per-file outcomes, use idempotent operations, and compensate/retry incomplete vector work. |
| 15 | **backend/app.py — create_conversation(), send_message()**; **backend/database.py — conversations schema** | Creation trims and caps title length; first message derives a title using whitespace normalization and a 58-character cap. Consider control-character normalization, safe display, and one shared title validator. |

## B. SQLite, persistence, and data consistency

| # | Primary source location | Expected investigation / review notes |
|---|---|---|
| 16 | **backend/database.py — conversations/messages schema, connect_database()** | Foreign keys are declared, and local sqlite3 executes PRAGMA foreign_keys=ON. Remote libSQL setup does not explicitly apply this pragma. Verify remote behavior and enforce cascade or explicit transactional deletes consistently. |
| 17 | **backend/database.py — SCHEMA, initialize_database()** | Startup only executes CREATE TABLE/INDEX IF NOT EXISTS. There is no schema version or migration runner. Add ordered, idempotent migrations and deploy additive changes before code requiring them. |
| 18 | **backend/app.py — messages_for(), get_messages(), send_message()**; **backend/database.py — idx_messages_conversation_created** | messages_for() uses ascending order with LIMIT 200, so it returns the oldest rows, not necessarily the latest. Clarify product semantics, query newest page first then reverse for display, and use cursor pagination. |
| 19 | **backend/database.py — connect_database(), get_db(), close_db()**; **backend/app.py — send_message()** | Local connection uses WAL/busy timeout, one connection per Flask app context. RAG call occurs before message writes, so no DB transaction is held during the model call. Keep transactions short and handle retryable lock errors carefully. |
| 20 | **backend/database.py — connect_database()** | Remote libSQL attempts to set sqlite3.Row and ignores unsupported assignment. Normalize row access behind an adapter or test both drivers' cursor/row behavior. |
| 21 | **backend/app.py — admin_overview(), admin_documents(), admin_ingestion_runs()**; **backend/database.py — indexes** | Overview issues several COUNT queries and recent-run query; document/run endpoints cap results but lack pagination. Review indexes, query plans, caching, and allowlisted identifiers. Current table names in the loop are hard-coded, not user-controlled. |
| 22 | **backend/rag.py — index_pdf_bytes(), _save_document()**; **backend/app.py — reindex_knowledge()** | SHA-256 is stored; upsert conflict key is filename. Filename is not a content identity, and stable manifest source IDs are only passed in reindex. Choose identity/version semantics and keep an audit trail of replaced content. |
| 23 | **backend/app.py — upload_knowledge(), reindex_knowledge(), finish_run()**; **backend/rag.py — index_pdf_bytes(), _save_document()** | Vector provider writes can succeed before relational commit. Failed batches roll back SQLite but cannot automatically undo provider writes. Model status explicitly and reconcile vector/SQL state after failure. |
| 24 | **backend/app.py — archive_document()**; **backend/rag.py — vector_store()** | Deletion branches on Pinecone config and uses source_id filter; local Chroma uses where. Verify namespace/filter semantics and count after deletion before marking archived; make the operation idempotent. |
| 25 | **backend/app.py — health()**; **backend/database.py — initialize_database()** | /health is a process response and does not execute a database query. Keep liveness cheap; add readiness that checks database connectivity and required dependencies without making an LLM request. |
| 26 | **backend/database.py — SCHEMA**; **backend/app.py — account routes** | There is no account-erasure endpoint. uploaded_by and created_by are not all foreign-key constrained. Design an authenticated/verified workflow, audit the request, delete or anonymize relational records, and address vectors and external trace retention. |
| 27 | **backend/app.py — get_conversation(), messages_for(), get_messages(), delete_conversation(), send_message()** | The owner check is performed before message operations; messages_for itself filters only by conversation_id. Preserve the ownership guard in every caller and add adversarial cross-user tests. |

## Review rubric

Score each scenario out of 10:

- 2 points: exact source file and function/route identified.
- 2 points: accurate request/data-flow explanation.
- 2 points: root cause correctly classified.
- 2 points: safe, minimal correction with relevant code.
- 1 point: meaningful verification plan.
- 1 point: privacy/security/reliability/cost trade-off identified.

A location-only answer is incomplete. Students should explain why the code behaves this way and how they would confirm the change.
